# A〜D/E Evaluation Protocol

## 目的

A〜D比較の最重要質問は、どれが最速かではない。

> どの方式が、必要情報を失わず、職員の精神的負担を最も減らせるか？

Kikumaeを勝たせるために、Bを使いにくくしたり、Cの要約Promptを弱くしたりしない。EはA〜Dの結果と設計妥当性を確認した後の第二段階とする。

## 条件

| 条件 | 参加者が見るもの | 除外するもの |
| --- | --- | --- |
| A | 住民の原文のみ | 整理カード、自動要約 |
| B | カテゴリ、人数、場所、要望、Safety確認等の合理的フォーム＋決定的ルール | LLM、Kikumae独自Organizer |
| C | 一般的な単純LLM要約＋原文リンク | Kikumae固有プロンプト、Safety Organizer、Evidence生成 |
| D | 原文保持、facts、requests、context、感情、Safety、evidence/source、不確実性、職員確認 | 根拠のない確定表示 |
| E | Structured-first。十分な情報はAI不要、曖昧・複雑相談だけAI補助 | すべての相談へのLLM必須依存 |

### CのBaseline Prompt

以下を固定する。

> 以下の避難者からの相談を、避難所職員が対応しやすいよう、重要な事実・要望を失わず簡潔に要約してください。原文にない情報は追加しないでください。不明・可能性・否定はそのまま示してください。

モデル、温度、生成設定、Prompt versionを記録する。Cを意図的に弱くしない。

## 参加者

### Pilot

3〜5人を最初のPilotとする。目的は効果証明ではなく、尺度・タイマー・ケース・Ground Truth・条件の公平性をデバッグすること。

### Practitioner Evaluation

Gate 1/2通過後、自治体防災担当、避難所運営経験者、保健師、施設管理者等5〜10人から探索する。必要に応じて12〜24人へ拡張する。学生Pilotの結果と混ぜない。

## ケース割付

- 20〜30基礎ケースを使用し、各ケースは意味が同等で文面が異なるバリアントを用意する。
- 同じ基礎ケースを同一参加者に複数条件で見せない。
- 1人の参加者は各条件を経験するが、条件ごとに別ケースを割り当てる。
- 条件順はLatin square等でカウンターバランスする。
- 単純、長文、怒り、非Safety強表現、Safety、否定、不確実性、訂正、外国語、複数問題を均衡させる。

## Primary KPI

各相談の把握・次の対応判断後に、総合的な精神的負担を1〜5で回答する。

1. まったく負担を感じなかった
2. 少し負担を感じた
3. どちらともいえない
4. かなり負担を感じた
5. 非常に強い負担を感じた

**Primary KPI: 重要情報の把握精度を実用上許容できる範囲に維持した状態での、この精神的負担スコア。**

### 負担を分ける質問

Primaryは総合負担1つに固定する。ただしSecondaryとして、次を分けて聞く。

- 相談文そのものを読む負担
- この相談に対応することへの心理的負担

「短いから楽」と「安全に対応できるから楽」を区別するため、自由記述で理由も確認する。

## Guardrails

- 重要情報正答率95%以上を目標。最良条件より3ポイント超低下しない。
- Critical Safety false negative 0。
- 要望・意図・否定・不確実性・伝聞・最新訂正・経緯を保持。
- 次の対応Actionの重大誤り0。
- 原文消失/改変0、重要主張の根拠不明0。
- Human-in-the-loopを維持。

## Secondary KPI

- 内容把握時間
- 対応判断時間
- 原文閲覧率と理由
- 読みやすさ、認知負荷
- 信頼感1〜5
- 情報不足を感じた割合
- 次の対応の分かりやすさ
- 引継ぎのしやすさ
- 強い原文へ直接曝露した回数

原文閲覧率の低下は、正答・Safetyが維持された場合のみ望ましい結果と解釈する。

## Ground Truth

AI出力をGround Truthにしない。人間2名がケース作成時に、重要な事実、要望、場所、人数、Safety、不確実性、最新訂正、対応に必要なActionを確認して固定する。

`ambiguous` は不明のまま採点し、AIが推測して正答したことにしない。

## 手順

1. 練習2件。
2. 条件順・ケース割付を確認。
3. 相談を表示。
4. 参加者が次の対応を判断できた時点でタイマー停止。
5. Ground Truthに基づく重要情報、Safety、Actionを回答。
6. Primary精神的負担、読解負担、対応負担、信頼感を回答。
7. 原文を開いたか、開いた理由を記録。

## 成功条件（評価開始前に固定）

- Dの総合精神的負担中央値がAより1.0ポイント以上低い。
- Dの重要情報、Safety、意図/不確実性、対応判断がGuardrailを満たす。
- DがBまたはCに対して少なくとも1つの明確な業務上の優位性を示す。
- 原文消失0、Human-in-the-loop維持。

## Failure条件

- 精神的負担がAとほぼ変わらない。
- 精神的負担は下がるが、情報・Safety・意図・不確実性・Actionを失う。
- CとDが同等で、D独自の複雑さを正当化できない。
- Bが負担、正答、速度、導入容易性でDを上回る。
- Aが最も信頼され、整理がかえって不安や確認負荷を増やす。

## 分析

- Primaryは条件別の中央値、分布、個別失敗例を示す。
- D−Aの差を最重要にする。
- Primary差だけでなく重要情報正答率を同じ表で報告する。
- 小標本Pilotでは効果を断定しない。
- Practitionersでは職種、経験、ケース難易度、順序を層別する。
- 精神的負担が下がった理由を、短さ・信頼・原文曝露・判断しやすさに分解する。

## Eの追加条件

Eは、Dの精神的負担低下が確認されたが、毎回のAI整理が不要かを検討する段階で実施する。EがDと同等以上なら、AIを必要案件だけに限定する構成へPivotする。
