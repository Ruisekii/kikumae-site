# Validation Master Plan

## 1. Current Goal

Kikumaeを成功させることではなく、**避難所職員の精神的ストレスが住民対応と関係する問題として本当に存在するか、そしてKikumaeがその負担を既存手段より安全に減らせるかを判断すること**が現在の目的である。

### Purpose

避難所職員の精神的ストレス軽減。

### Mechanisms / Outcomes

- 刺激の強い原文を毎回直接読まなくて済む。
- 事実、要望、経緯、感情、Safety、不確実性を分けて把握する。
- 引継ぎ時の心理・認知負荷を下げる。
- 外国語、入力困難、情報不足による理解負担を下げる。

### Guardrails

- 原文、重要情報、Safety、意図、不確実性を失わない。
- AI整理を正本にしない。
- Human-in-the-loopを維持する。

## 2. What remains unproven

- 住民対応による精神的ストレスが職員の主要課題か。
- 強い感情を含む文章への直接曝露が負担の主要因か。
- Kikumaeが精神的負担を下げるか。
- フォーム、単純LLM要約、原文のみよりKikumaeが優れるか。
- 整理によって重要情報、Safety、意図、不確実性が保たれるか。
- 住民が受付・進捗表示によって安心するか。
- 現行業務に置く責任者、入口、既存システム連携があるか。

現在の合成評価、Safety 100%、HTTP成功率は上記の未証明を埋めない。厳格Evidenceは170件中strict pass 0件であり、実職員による評価は未実施である。

## 3. Problem Interview plan

まず3〜5人、その後必要なら5〜10人程度の実務者へ聞く。Interview前半ではKikumae、AI、感情分離、LLMを説明しない。

最初に、

> 避難所運営の中で、精神的に最も負担が大きい業務は何ですか？

と聞き、住民対応、苦情、繰り返し要求、強い怒り、不安、パニック、外国語、夜間、情報不足、引継ぎが自発的に出るか確認する。抽象的な「大変」ではなく、最後に起きた具体例、誰が対応し、どう記録し、何が負担だったかを聞く。

最後にのみ、原文を保存し、場所・要望・Safety等を整理して職員が確認する試作を提示する。役立つ部分だけでなく、不要・危険・使わない理由・既存方法との重複・AIを使わない方がよい部分を聞く。

## 4. Who to interview

- 自治体防災担当
- 避難所運営経験者・運営委員
- 施設管理者、学校の防災担当
- 保健師、DHEAT、福祉担当
- 災害ボランティア、社協、外国人・要配慮者支援
- 教員等は予備候補

役割、経験、組織、記録媒体を分けて記録する。実在住民・被災者データは収集しない。

## 5. A〜D/E experiment

### A〜D

- A: 原文のみ。
- B: AIなしの合理的な構造化フォーム＋ルール。
- C: 通常利用を想定した単純LLM要約＋原文リンク。Kikumae固有ロジックなし。
- D: 原文保持、facts、requests、context、感情、Safety、evidence/source、不確実性、職員確認。

### E（第二段階）

Structured-first。情報が十分ならAI不要とし、曖昧・自由記述・複雑な相談だけAI補助へ送る。A〜D Pilotが成立し、必要性がある場合のみ追加する。

30基礎ケースを各条件へ割り付け、同じ相談を同一参加者へ複数条件で見せない。条件順はランダム化・カウンターバランスする。Ground TruthはAI出力から作らない。

## 6. Primary KPI

**重要情報の把握精度を実用上許容できる範囲に維持した状態での、職員の主観的精神的負担。**

1〜5段階で、相談の把握・次の対応判断後に測定する。読解負担と対応判断負担はSecondaryとして分ける。

暫定Success Thresholdは、Dの総合精神的負担の中央値がAより1.0ポイント以上低く、Guardrailを満たすこと。Pilotではこの効果を証明せず、設計妥当性だけを確認する。

## 7. Guardrails

- 重要情報正答率95%以上を目標。最良比較条件より3ポイント超低下しない。
- Critical Safety false negative 0。
- 意図、否定、不確実性、伝聞、最新訂正、経緯の保持。
- 対応判断精度の重大誤り0。
- 原文消失/改変0、根拠のない確定主張0。
- AI停止・翻訳失敗・通信障害時もSafetyと原文を保持。

## 8. Pilot

最初は3〜5人、20〜30ケース程度で実施する。目的は効果証明ではなく、ケース難易度、Ground Truth、A〜Dの公平性、CのBaseline、Dの表示、タイマー、精神的負担尺度の妥当性を確認すること。

Pilot成功条件は、手順完了率90%以上、欠損/操作不能5%未満、重大Safety見逃し0、参加者が尺度と設問を理解すること。Pilot結果からストレス削減率や現場利用を主張しない。

## 9. Practitioner Evaluation

Gate 1とGate 2を通過した場合のみ、自治体防災担当、避難所運営経験者、保健師、施設管理者等5〜10人から探索し、必要なら12〜24人へ拡張する。学生Pilotと混ぜない。

Primaryは精神的負担、Guardrailは正答、Safety、意図/不確実性、対応判断、原文保持。原文閲覧率は、低ければよいとはせず、閲覧理由と正答を併記する。

## 10. Success Criteria

- Core Problemが複数の実務者から具体例付きで確認される。
- DがAより精神的負担の中央値を1.0ポイント以上下げる。
- DがBまたはCに対して少なくとも1つ明確な業務上の価値を示す。
- 重要情報正答率、Safety、意図/不確実性、対応判断のGuardrailを守る。
- 原文消失0、Human-in-the-loopを維持する。

## 11. Failure Criteria

- 精神的負担がAとほぼ変わらない。
- 精神的負担は下がるが、重要情報、Safety、意図、不確実性、対応判断が低下する。
- CとDが同等で、D独自の複雑さを正当化できない。
- Bが負担、正答、速度、導入容易性のすべてでDを上回る。
- Interviewで住民対応ストレスが主要課題として確認されない。
- 原文、Safety、内部メモ、個人情報、復旧境界に重大な問題が残る。

## 12. Kill Criteria

- 5〜10名の実務者からCore Problemが確認できない。
- 2回の実務者評価でDがA/B/CをPrimary KPIで上回らない。
- Safety false negative、原文消失、重大な意味変形を閉じられない。
- 本当の負担が人員・物資・権限など別問題で、Kikumaeの境界内で改善できない。
- 運用責任者・保持責任者・訓練機会がない。

## 13. Possible Pivot

- AI Organizer → 職員への一次遮蔽・段階表示。
- 自由記述中心 → Structured-first。
- AI中心 → 原文保存＋フォーム＋Safety＋職員カード＋CSV/API Export。
- 複雑なLLM整理 → 必要な相談だけAI補助。

AIを完全に削除しても職員の精神的ストレスがより大きく減るなら、それを採用する。目的はAI利用ではない。

## 14. Next Gate

1. Problem Interview
2. Core Problem Validation
3. A〜D Pilot（必要ならE）
4. Mental Load + Information Accuracy比較
5. Practitioner Evaluation
6. KEEP / REFINE / PIVOT / STOP

これらが終わるまで新機能開発、モデル変更、公開デプロイ、Controlled Disaster Drillへ進まない。

## 最終原則

**目的は職員の精神的ストレス軽減。手段は検証結果によって変える。**
