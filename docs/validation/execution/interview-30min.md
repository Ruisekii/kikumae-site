# Problem Interview 30分版

## 目的

実務者から、具体的な過去事例、受付から完了までの作業、負担、代替策、失敗条件、運用責任を深掘りする。Kikumaeの説明は後半のみ。

## 時間配分

- 導入・同意: 2分
- 具体的な一件の再現: 6分
- 現在の受付と記録: 5分
- 情報不足・優先順位・引継ぎ: 7分
- 負担・制約・代替: 5分
- Concept Test: 4分
- 終了: 1分

## 実戦台本

### 0. 最初の自由回答

「避難所運営の中で、精神的に最も負担が大きい業務は何ですか？」と聞く。住民対応、苦情、強い感情、外国語、夜間、情報不足、引継ぎを先に列挙しない。参加者が自発的に挙げた内容と、挙げなかった内容を記録する。

### 1. 具体的な一件

「最近の災害、訓練、または避難所運営で、住民の困りごとが届いてから対応が終わるまでの一件を思い出してください。最初に何が起き、誰が受け、どこへ記録し、誰が判断し、どう引き継ぎましたか？」

追加質問:

- 最後にそれが起きたのはいつですか？
- 何人くらいが関わりましたか？
- 何分または何時間かかりましたか？
- 途中で聞き直した情報は何ですか？
- 最終的に何をもって完了としましたか？

### 2. 現在の受付

- 口頭、紙、電話、LINE、Web、巡回、支援者経由の比率はどうですか？
- 最初に受ける人と最終判断者は誰ですか？
- 記録しない相談、記録が複数箇所に分かれる相談はありますか？
- 同じ内容が複数人から来たとき、どの単位でまとめますか？

### 3. 情報不足と正確性

- 人数、場所、時刻、症状、物資量、経緯、本人の訂正のどれが抜けますか？
- 情報不足に気づくのはいつですか？
- 伝聞や「かもしれない」はどう記録しますか？
- 否定表現や複数問題はどう扱いますか？

### 4. 優先順位と引継ぎ

- 緊急性を誰が判断し、どの経路で速報しますか？
- 大量の相談が重なったとき、何を後回しにしますか？
- 担当者、対応中、保留、完了はどこで分かりますか？
- 二重対応、引継ぎ漏れ、未確認のまま埋もれた例はありますか？

### 5. 負担と代替

最初に自由回答で聞く。

> 避難所運営で、身体的・時間的・精神的に負担が大きい業務は何ですか？

自発的に出た内容だけを深掘りする。

- その負担は誰に集中しますか？
- どの時間帯・状況で増えますか？
- 紙、巡回、ホワイトボード、Excel、既存システムの方がよい場面は？
- 何を自動化してはいけませんか？

### 6. 障害・非デジタル

- 停電・通信断・端末故障・職員交代時に最低限必要な情報は？
- スマートフォンを使えない住民をどう取り込むか？
- 共用端末・確認URL・個人情報の消去と権限はどう管理するか？

### 7. Concept Test

> 住民からの相談原文はそのまま保存し、場所・要望・背景・Safety情報などを整理して、職員が短時間で確認できる仕組みを試作しています。

質問:

- どこが役立ちそうですか？
- どこが不要ですか？
- どこが危険ですか？
- なぜ使わないと思いますか？
- 既存の方法と比べて何が面倒ですか？
- AIを使わない方がよい部分、逆に人に任せるべき部分は？
- 誰が入力・確認・保守・導入判断を担えますか？

回答は感想ではなく、直前までに確認した現在の事実と分けて記録する。
