# Kikumae 現状把握

## 判定

既存実装は「原文を残し、Safety Guard と職員向け整理を分離する」技術的な土台まで進んでいる。人間の職員負担が下がったこと、現場で継続利用されること、自治体業務に適合することは未評価である。

|区分|確認内容|
|---|---|
|実装済み|匿名受付、FAQ、進捗、原文保持、Incident schema、Safety Guard、職員向け整理カード、翻訳レイヤー、local-rules fallback、Provider境界|
|実装済み（限定的）|多言語会話・職員向け日本語訳、音声入口、ローカルLLM接続境界|
|未実装/未完|完全オフラインE2E、実機アクセシビリティ検証、実運用の引継ぎ/担当割当、本番相当の同時利用、自治体システム連携|
|評価済み|固定合成ケースの Safety、schema、レイテンシ、モデル比較、障害注入の一部|
|未評価|実職員の時間・正答率・心理負担、住民の到達率、実災害/訓練での導入効果、導入費用対効果|
|確認済み事実|Phase 2B/2Cの固定評価ではSafetyは高成績だが、抽出の重要事実保持と同時利用には弱点がある|
|仮説|相談の受け手が感情的文章を大量に読むことが主要な負担で、整理カードが負担を減らす|

## 内部数値の扱い

固定合成110件ではSafety recall/precision 100%と報告されるが、実災害の安全性を保証しない。Qwen抽出は重要事実取りこぼしが残り、10同時利用ではfallbackが発生した。人間評価は未実施であり、「職員ストレス○%削減」は主張不可。

## 判断

技術実装は検証可能な状態だが、価値仮説は **Unsupported**。次の作業は機能追加ではなく、現行業務の観察・問題インタビュー・比較実験である。
