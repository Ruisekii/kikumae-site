## 2. 変更仕様（優先順）

**P0** ＝ 9/24 提出前にシートに書き、デモで見せられる形にする（実装が軽い・既存を活かす）
**P1** ＝ 提出後〜最終審査（2027-01-11）まで
**P2** ＝ 自治体との実証段階

### P0-1 本部ダッシュボードと定時報告（H3・H11）

- **目的**：避難所からの「上げる」経路と、本部からの「返す」経路を1本にする。ガイドライン3-3/3-5の定時報告を、職員が書かずに済む形で出す。
- **画面**：`/hq`（本部ロール）。全避難所を1行ずつ：未解決件数／緊急候補／物資要請（品目・数量）／最終更新。行を開くとその避難所の issues。上部に「お知らせを全避難所へ配信」。
- **データ**：`portals`（避難所）に `hq_id` を持たせ、本部は複数避難所を束ねる。`issues` に `hq_status`（未確認／本部対応中／回答済み）。`broadcasts`（本部→避難所→避難者のお知らせ、言語別本文）。
- **定時報告**：ボタン1つで「避難所名・避難者数（入力値）・未解決件数・緊急件数・物資要請一覧・特記」を3-5の様式順で生成（テキストとCSV）。
- **受入条件**：本部が回答すると、束ねられた相談者全員の状態が「本部回答済み」になり、避難所職員の画面から消えずに「本部から回答あり」バッジが付く。
- **根拠**：S25 p.18（3-3・3-5）、E4、B5、F5。

### P0-2 交代時の申し送りカード（H4）

- **目的**：応援職員が1週間〜10日、地元職員が12時間交代で入れ替わっても、状態が人に紐づかない。
- **画面**：職員画面の先頭に「今日の避難所」カード。①未解決（古い順）②要緊急確認③**約束済み**（「○時に配布と伝えた」を自動抽出）④本部待ち⑤前任の内部メモ。印刷可能（紙で渡す運用にも合わせる）。
- **データ**：既存の `issues`・内部メモを集計するだけ。約束済みは公開返信文から時刻表現を抽出してタグ付け。
- **受入条件**：新任が「今日の避難所」だけを読んで、最初の1時間の行動を決められる（受入テスト：前任のメモを見ずに3件処理できる）。
- **根拠**：B4・B5（S1）、C1、`02` t_handoff。

### P0-3 代理入力（H6）

- **目的**：自分では入力しない・できない人の声を落とさない。
- **画面**：職員画面に「代わりに受け付ける」。区画・人数・内容を職員が入力し、本人には受付番号を紙（レシート印刷または手書き）で渡す。運営委員ロールでも可。
- **データ**：`questions.submitted_by`（本人／職員／運営委員／家族）。代理分は統計で分けて見える。
- **受入条件**：代理入力した相談も同じ状態遷移・同じ通知に乗る。
- **根拠**：S23、S24、S22。

### P0-4 「対応できない」を正式回答にする（H10 ③④）

- **目的**：理不尽・不可能な要求に職員が個人で向き合わない。組織の回答として返す。
- **画面**：対応パネルに「対応できない（本部承認）」。理由の定型（物資なし／安全上／制度外／他機関へ）＋代替案。本部承認で確定し、束ねた相談者へ一括返信。
- **データ**：`issues.status = declined`、`declined_reason`、`approved_by`。
- **受入条件**：職員側の画面では原文（怒りの文）は既定で伏せ、要点と「対応できない」テンプレだけで処理が完結する。
- **根拠**：G2・G5、[N] の実例。

### P0-5 職員負荷メーター（H17。設計のみP0、実装P1）

- **目的**：豊田市の「アナログでも検証できていない」に、システム自身の記録で答える。
- **指標**：日別受付件数、感情ラベル「強い不満」の割合、未解決の滞留時間、代理入力の割合、返信までの中央値、職員1人あたり件数。避難所別・日別。
- **用途**：本部の配置判断／事後検証／ROIモデルの既定値を実測に置換（`03` の6問に対応）。
- **根拠**：G6、B1、`02`。

## 4. 効果測定の設計（豊田市の問いに答える）

システムが自動で残す数値と、ROIモデル（`02`）の入力の対応：

| ROIの入力 | システムのログ | 取り方 |
|---|---|---|
| Q（1日の相談件数） | `questions` の日別件数 | 自動 |
| t_intake（1件の受付分） | 代理入力の開始〜登録の時間、紙取り込みの件数 | 自動（代理・紙のみ） |
| t_handoff（引継ぎ分） | 申し送りカードの閲覧から最初の操作までの時間 | 自動 |
| r（再問合せ率） | 同一受付番号からの2回目以降の送信 | 自動 |
| t_report（本部報告分） | 定時報告の生成回数（手書きなら0） | 自動 |
| f（削減率） | 訓練での対照比較（紙班 vs システム班） | 訓練で実測 |

訓練1回で f 以外は取れる。f は Phase 2F の人間評価と同じ枠組みで訓練時に測る。
