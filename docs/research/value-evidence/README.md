# 対価を示すための根拠パック（2026-09-16）

「このサービスに払う価値があるか」を、支払者と災害経験のある職員に**数字で**説明するための資料。
`parallel-validation/` が「問題は存在するか」を定性的に検証したのに対し、ここは
**規模・時間・単価・相場**を一次資料から集め、ROIの計算式と、それを埋めるヒアリング設問にした。

## 30秒で言えること（すべて出典あり）

1. 避難所運営は、地元職員が2人1組・交代なしで始まり、応援職員が「毎日人が変わる」形で引き継ぐ。要望は用紙に書いて配送業者が本部へ運んだ（熊本地震・消防防災科学センター）
2. 能登では応援職員が延べ**115,959人日**入り、その主業務が避難所運営だった（総務省）。輪島市では事務職の**77%が月100時間超**の時間外（朝日新聞）
3. 内閣府の検証は「避難者の要望を詳細に把握するまでに時間を要した」「要望を細かく把握し共有できる仕組みが必要」と明記。中央防災会議は「**避難者自身が入力することも含め**、職員の負担軽減を検討することが望ましい」と書いた
4. 導入費は緊急防災・減災事業債（充当率100%・交付税70%、**令和12年度まで延長**）の対象。自治体の実質負担は3割
5. 相場は J-LIS が「年185千円＋人口×10円/人」、民間SaaSが「初期40万＋年112万〜」。相談層はその下に置く
6. **正直な結論**: 災害時の人件費だけでは、中規模市で1回373万円・年額60万なら6年に1回の災害が要る。平時利用・財政措置・応援職員コスト・休職回避・県一括のどれが効くかをヒアリングで確かめる

## まだ足りていないところ（面談で検証する仮説）

製品側の不足は Codex が `docs/roadmap-from-goal.md` で管理している。ここには**面談で答えが出るもの**だけ置く。

- 相談は文章で来るのか、口頭が中心で職員が代わりに入力する運用になるのか（Q1・反証）
- 避難者が「自分の相談がどうなったか」を見られることに、実際どれだけ価値があるか（Q4）
- 交代時の引継ぎは、相談の状態が残るだけで本当に短くなるか（Q3）
- 本部側は避難所ごとの相談を集約した画面を欲しがるか、既存の県アプリで足りるか（Q5・既存手段）
- 通信断のとき、何が残っていれば使い続けられるか（反証）
- 支払者は市か県か国か。緊防債・特交を使った経験があるか（支払構造）
- 「なくなると困る」と言える人がいるか（Killer Question）
