# ヒアリング追加設問 — ROIモデルの入力を「数字」で埋める

既存の `docs/municipal-interview-guide.md` は現行フローと役割を聞く。**この追補は数字を取る。**
相手は災害を経験した職員。営業ではなく、**その人が実際に体験した1日**を数えてもらう。
「だいたい」でよい。分からなければ「分からない」を記録する（ゼロや推測で埋めない）。

冒頭で伝えること: 「効果を約束しに来たのではなく、いまの運営で何に何分かかっているかを
教えてほしい。数字が取れないと、この製品が見合うかどうか自分たちにも判断できない」

## 0. 前提の確認（2分）

- どの災害、どの避難所（規模・期間）、あなたの役割と勤務形態（交代の有無・1シフト何時間）
- 避難者数のピークと、そのときの職員数（地元／応援の内訳）

## 1. 必ず取る6つの数字（20分）— モデルの主要入力

| # | 設問 | 埋まる入力 |
|---|---|---|
| Q1 | **1日に、避難者からの相談・要望・問い合わせは何件くらい来ましたか？** 一番多かった日と、落ち着いてからの日で。紙／口頭／電話／LINE等の内訳は？ | Q（件数）、文章比率 |
| Q2 | **1件を受けて、記録して、本部に伝えるまで何分かかりましたか？** 誰が、何に書いて、どう運びましたか（用紙・電話・タブレット）？ | t_intake、現状経路 |
| Q3 | **交代のとき、引継ぎに何分かけましたか？** 1日何回交代？ 引継ぎで抜けて困ったことは？（連絡先が分からない、同じ人に二度聞いた、など） | n、t_handoff、引継ぎ漏れの実例 |
| Q4 | **「いつ届きますか」「あれはどうなりましたか」と同じ人に何度聞かれましたか？** 1日何件くらい、1回何分？ 掲示で減りましたか？ | r、t_re |
| Q5 | **避難所から本部へ、要望をまとめて報告するのに1日何分・何回？** その報告はどう使われましたか（返事が来た／来ない）？ | t_report、集約の実態 |
| Q6 | **応援職員は何人、何日、何をしましたか？** 地元職員が本来業務に戻れたのはいつ？ 応援職員への説明に毎日何分？ | 応援人日、引継ぎ負荷の外部分 |

聞き方のコツ: 「平均」ではなく「**最悪だった日**」と「**普通の日**」の2点で聞く。モデルには両方入れられる。

## 2. 現状手段の速さ（反証を取る。10分）

製品が勝てない領域を先に知る。

- 紙・ホワイトボード・口頭のほうが**速かった**場面は？ それはなぜ？
- 避難者のうち、スマホを自分で使えない人はどれくらい？（高齢者・停電・充電・通信）
- 文章で届いた相談は全体の何割？ 口頭が中心なら、職員が代わりに入力する運用は現実的か？
- 通信が切れた時間帯はどれくらい？ そのとき何が残っていれば業務が続いたか？
- 既存のシステム（避難者名簿、物資、県のアプリ、LINE）は何を使い、何が使われなかった？ 理由は？

## 3. 「なくなると困る」テスト（5分）

Codexの調査での Killer Question。

- あの災害のときに**もし**この製品があったら、具体的に**どの日の・どの作業**が変わりましたか？
  （変わらない、という答えも重要な結果）
- 逆に、これがあると**邪魔になる**場面は？

## 4. 支払いの構造（10分）— 金額は言わない

- 防災関連のシステムは**誰の予算**で、**誰が決裁**しますか？（防災課／情報政策課／総務）
- 緊急防災・減災事業債や特別交付税を、システム導入で使ったことがありますか？ 手続きは誰が？
- 県が一括で入れる仕組み（J-LISのクラウド型被災者支援システムなど）を使っていますか？ 感想は？
- **Van Westendorp**（順に4問。金額はこちらから出さない）
  1. 年額いくらなら「高すぎて検討外」ですか？
  2. いくらなら「高いが、検討はする」？
  3. いくらなら「安すぎて品質が不安」？
  4. いくらなら「お得だ」？
- 平時にも使えるなら（常設の相談窓口・訓練）、災害専用と比べて評価は変わりますか？

## 5. 製品を見せる順番（デモは最後。10分）

根拠 → 製品の順で見せる。

1. 数字台帳から3つだけ見せる: 熊本市の「記入用紙を配送業者が本部へ」[S1]、内閣府の「要望把握に時間を要した」[S3]、中央防災会議の「避難者自身が入力…負担軽減」[S14]
2. 「あなたの現場はこれと同じでしたか、違いましたか」と聞く
3. 製品は**避難者側→職員側**の順に、1件の相談が届いて状態が変わるところまでを1分で
4. 触ってもらい、「初見で迷った箇所」を記録する（既存ガイドの観察指標）

## 6. 記録テンプレート

```
災害:            避難所:            期間:         役割:        交代: 
避難者ピーク:    地元職員:    応援職員:    
Q1 件数/日  最悪:     普通:     内訳(紙/口頭/電話/他):
Q2 t_intake 分:      経路:
Q3 交代 回/日:   引継ぎ 分/回:    漏れの実例:
Q4 再問合せ 件/日:   分/件:
Q5 報告 分/日:   回/日:   返事:
Q6 応援 人 × 日:   本来業務復帰:   説明 分/日:
反証: 紙が速かった場面 / スマホ不可の割合 / 文章比率 / 通信断の時間
なくなると困る: 
予算・決裁:        財政措置の経験:        県一括: 
VW: 高すぎ:   高いが検討:   安すぎ不安:   お得:
平時利用の評価: 
デモで迷った箇所:
```

ヒアリング後、Q1〜Q6 を `02-roi-model.md` の既定値と置き換えて再計算し、
**その人の現場だけのROI**を1枚にして返す。それが次の面談の入口になる。
