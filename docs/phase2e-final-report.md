# きくまえ 避難所版 — Phase 2E 最終レポート

## 1. 結論

Phase 2Eでは、KikumaeのAIを「会話を続けるAI」中心から、「職員が安全に状況を把握するための証拠付き整理」中心へ再定義した。住民側のConversationは短く受け止め、不足項目を最大1つ確認するだけにする。Safety GuardはLLMと独立させる。職員画面には、一文要約だけでなく、事実・要望・経緯・感情・不確実性・Safetyを分けて表示する。

4B Extractionと整理カードは毎回二重に必須実行しない。単純な案件はSafety＋決定的な初期カードで即時表示し、4Bは複雑案件の候補補助として非同期に扱う。

## 2. 実装した変更

- `app/lib/staff-organization.ts` に `StaffOrganizationProvider` と証拠拘束型の実装を追加。
- 職員向けカードを `facts` / `requests` / `context` / `emotionalState` / `uncertainPoints` / `safetySignals` に分離。
- 各項目へ `source`、`confirmed`、`evidence`、`messageId` を付与。
- 原文を `originalText`、原言語を `originalLanguage`、作成時刻を `createdAt`、相談単位IDを `originalMessageId` として保存。
- `staff_organization` を質問レコードへ保存し、4B停止時も初期カードを失わないようにした。
- 管理画面に「職員向け整理カード」を先頭表示し、日本語訳・原文・会話履歴タブを追加。
- `/api/ai/voice` に `mode=organize` を追加。公開実行ではモデルを必須にせず、`auto`の安全なfallback境界を維持。
- Phase 2E固定25件と障害注入評価を `scripts/phase2e-*` に追加。

## 3. AIの責務

| レーン | 役割 | 最終判断 |
|---|---|---|
| Conversation | 受け止め、短い確認、利用者への次の案内 | しない |
| Safety Guard | 原文から医療・火災・暴力等を先行検出 | 職員速報の候補にするが、職員判断を置き換えない |
| Incident / deterministic card | 原文・本人選択・Safetyから即時の初期構造を作る | しない |
| 4B Extraction | 複雑案件の事実抽出候補 | 原文を上書きしない |
| Staff Organization | 職員向けに事実・要望・経緯・感情・不確実性を分離 | 職員確認が必要 |
| Translation | 職員が読める補助表示 | 正本にしない |

## 4. 原文と出所

原文は質問受付時点で保存し、整理カードの項目には根拠テキストとメッセージIDを付ける。強い表現の「死んじゃいますよ」「最悪」は、Safety条件がない限り感情・不確実性として扱い、生命危険の事実へ変換しない。否定の「火事ではありません」「暴力はありません」もSafety Guardの否定処理を通過させる。

## 6. 障害時

`organization-down` の障害注入で、`organization-fallback`、Safety配列保持、相談原文保持を確認した。Ollamaが使えない公開環境では、Conversation / Extractionはlocal-rulesへfallbackし、原文・Safety・初期カードを失わない。重要な回答の自動送信・自動確定は追加していない。

## 7. 職員の心理的負担を測る人間評価プロトコル

同じ相談を、A「原文のみを先に読む」条件と、B「整理カードを先に読む」条件で提示する。順序はランダム化し、同じ職員が連続して同一文章を見ない。各条件で以下を測る。

- 初回対応開始までの時間（秒）
- 人数・場所・時刻・症状・要望の読み取り正確度（正答率）
- 職員が原文を開いたか（有無）
- 主観的負担（1:負担なし〜5:非常に負担）
- 可読性（1〜5）
- 対応に使える度合い（1〜5）
- Safetyと不確実性を正しく区別できたか

「怒りが何%減った」とは測定しない。主KPIは初回対応時間、情報正確度、原文を開かずに対応できた割合、主観的負担の分布とする。医療・火災・暴力の正答を最優先し、整理カードが原文を隠していないことを確認する。

## 9. 残っているリスク

1. 公開Siteから避難所内localhostのOllamaへは到達できず、公開版のQwenは利用できない。
2. ブラウザWeb Speech APIの音声が完全ローカルとは確認できない。現在もBrowserASRProviderの説明を維持する。
3. 固定25件はProvider回帰としては有効だが、実際の職員のストレス低減を証明しない。人間評価が必要。
4. 整理カードの初期値は決定的処理であり、複合・曖昧な長文の網羅性は4B候補と原文確認に依存する。
5. 職員による構造化項目の修正履歴を、次Phaseで明示的な `staff_edit` 操作として保存する。

- 4B後処理を永続キューにして再起動・再試行・重複排除を確認。
- 多言語の職員向け翻訳と原文の意味保存を、実データに近い固定セットで追加評価。
