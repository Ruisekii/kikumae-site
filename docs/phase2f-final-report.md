# Phase 2F 最終レポート

## 1. 結論

Phase 2Fでは、新しい大規模機能を追加するのではなく、Phase 2Eの整理カードが「職員の情報把握・対応判断の負担を減らせるか」を測定可能にしました。

現時点では人間参加者によるA/B評価を実施していないため、職員の精神的負担が減った、読み取り時間が短くなった、という効果はまだ主張できません。今回確認できたのは、次の人間評価に必要なデータ・手順・安全側の回帰評価が揃ったことです。

また、固定100件の合成評価では、公開版のfallbackはSafetyを高い再現性で守る一方、重要事実・文脈・不確実性の保持に改善余地が残りました。ローカルQwen3.5:4bは一部の構造化精度を改善しましたが、代表10件でも遅く、原文にない値を含むケースがあったため、標準処理には昇格させていません。

## 2. 変更点

- `scripts/phase2f-cases.mjs`
  - 日本語・英語・中国語・韓国語・混在を含む100件の匿名合成固定セットを追加。
  - 水、トイレ、物資、医療、安全、通常相談、境界例、訂正、多言語、感情表現の10カテゴリを各10件収録。
  - 否定、不確実性、強い怒り、Safetyと感情の分離、同一相談内の訂正を含む。
- `scripts/phase2f-eval.mjs`
  - fallback全100件と、任意のQwen抽出結果を同一ケースで比較。
  - 重要事実、文脈、要望、感情、不確実性、訂正、Safety、hallucination、欠落、矛盾、レイテンシを記録。
  - fallbackは公開デモと同じ証拠拘束整理レーン、Qwenは任意のIncident Extractionレーンとして別集計。
- `scripts/phase2f-human-plan.mjs`
  - 参加者データを収集せず、A/B評価用の固定seed・ケース割当・匿名枠だけを生成。
- `docs/phase2f-human-evaluation-protocol.md`
  - 原文のみ（A）と整理カードあり（B）のカウンターバランス評価手順を追加。
- `docs/phase2f-human-evaluation-plan.json`
  - Pilot 4枠、実務者 4枠、計8匿名枠の計画。回答収集は未開始。
- `app/lib/safety-guard.ts`, `app/lib/staff-organization.ts`, `app/lib/multilingual-incident.ts`
  - 固定セットで見つかった否定、Safety境界、最新訂正、場所・数量・多言語表現の誤りを補正。
  - Safety Guardは引き続きAI出力より先に独立実行する。

## 3. A/B人間評価の設計

同じ相談を同じ参加者へA/B連続提示しません。ケースを2セットに分け、Group 1はA→B、Group 2はB→Aとし、同一ケース間に別ケースを挟みます。

条件Aは原文のみ、条件Bは原文を隠した整理カードを初期表示し、必要時だけ原文を開ける構成です。以下を記録します。

- 内容把握時間
- 対応判断時間
- 重要情報正答率
- 原文閲覧率
- 原文を開かずに適切対応できた率
- 1〜5の精神的負担、読みやすさ、把握しやすさ、対応判断のしやすさ、信頼感

Pilotと実務者を分け、学生評価だけから職員の精神的負担を推定しません。実災害相談・個人情報・実患者情報は使いません。

## 4. 固定100件の機械評価

評価日時：2026-09-09時点のローカル評価結果。データ自体の生成時刻はJSONに保存。

### 公開版相当 fallback（100件）

| 指標 | 結果 |
|---|---:|
| HTTP成功 | 100/100 |
| 重要事実保持率 | 137/241 = 56.8% |
| 文脈保持率 | 19/32 = 59.4% |
| 要望分類正解率 | 89/100 = 89.0% |
| 感情検出再現率 | 21/31 = 67.7% |
| 感情の誤検出 | 1件 |
| 不確実性保持率 | 8/11 = 72.7% |
| 訂正処理正解率 | 7/8 = 87.5% |
| Safety recall | 26/26 = 100% |
| Safety precision | 26/(26+0) = 100% |
| Safetyラベル一致率 | 25/26 = 96.2% |
| hallucination | 0件（証拠アンカー評価） |
| 矛盾 | 0件 |
| レイテンシ P50 / P95 / 最大 | 72ms / 124ms / 170ms |

fallbackのhallucination 0件は、原文・既存Incident・Safetyに証拠を限定する実装上の指標です。人間による意味判定を代替するものではありません。重要事実保持率56.8%は、職員カードとして現状のまま十分とは言えない値です。

### ローカルQwen3.5:4b Incident Extraction（代表10件）

| 指標 | 結果 |
|---|---:|
| HTTP成功 | 10/10 |
| 重要事実保持率 | 15/22 = 68.2% |
| 文脈保持率 | 6/6 = 100% |
| 要望分類正解率 | 10/10 = 100% |
| 感情 | Incident Schemaに項目がなく評価対象外 |
| 不確実性 | 対象0件 |
| 訂正処理正解率 | 0/1 = 0% |
| Safety recall / precision | 3/3 = 100% / 3/(3+0) = 100% |
| 重要事実の近似hallucination | 5件、10件中4割 |
| 重要事実欠落 | 7件、必要22件中31.8% |
| 矛盾 | 0件 |

Qwenはfallbackより重要事実・文脈・要望分類で良い結果を示しましたが、評価は代表10件に限られ、速度と原文忠実性に課題があります。感情品質はIncident Schemaに `emotionalState` がないため、Qwenの性能として主張していません。

## 5. Safetyと感情の分離

高熱、意識・呼吸異常、火災、暴力、強い胸痛などは、Conversationや整理カードの生成結果を待たずSafety Guardで検出します。怒りや「最悪」などの強い表現だけではSafetyとしません。

否定表現「息苦しくはないが胸が痛い」、火災否定、暴力の予告、意識あり、高熱ではない、の境界例を含む回帰確認を行い、今回の固定セットではSafety recall/precision 100%でした。ただし、これは合成データに対する結果であり、実災害の多様な表現に対する保証ではありません。

## 6. 公開版とローカル版の差

- 公開版：localhostのOllamaへ接続できないため、Phase 2Eの証拠拘束fallbackで動作。
- ローカル版：Ollama上の `qwen3.5:4b` を任意のIncident Extractionとして評価。
- 公開版がQwenを実行している、または公開版の結果が完全ローカルである、とは扱わない。
- Browser Speech APIの音声処理も、ブラウザ提供元への送信可能性を残すため、完全ローカル・外部送信なしとは表示しない。

## 7. まだ実施していないこと

- 実際の職員・実務者によるA/B評価
- 100件全件でのQwen4B評価
- 条件別の把握時間・対応判断時間・主観負担の比較
- 実運用での職員一人あたりの担当数と原文閲覧率の検証
- 実災害データを用いた評価

したがって、現時点で「職員の精神的負担が何％減った」といった数値はありません。

## 8. 残る重大リスク

1. fallbackの重要事実保持率が56.8%で、カードだけを正本にしてはいけない。
2. 不確実性保持率72.7%で、可能性・伝聞・本人の訂正を確定事実へ変換しない追加対策が必要。
3. Qwen4Bは代表10件でもP50約24秒で、受付同期処理には不適切。
4. Qwenの近似hallucination 5件は、職員画面へ自動確定表示するには危険。
5. 人間評価が未実施で、負担軽減仮説は未検証。
6. 音声認識と音声合成のオフライン性はブラウザ依存で、完全ローカル保証がない。

## 9. Phase 2Gの提案

- Phase 2Fプロトコルに沿った匿名合成データでのPilot実施後、自治体・避難所実務者による小規模評価へ進む。
- 整理カードの各項目を職員が修正・確定でき、修正前後と原文根拠を `staff_edit` として保存する。
- 重要情報保持率の低い項目をカテゴリ別に改善し、同じ100件で再評価する。
- Qwen4Bは全100件を測定できるGPU/RAM環境で再評価し、遅延とhallucinationを含めて採否を判断する。
- 避難所LAN上のDB・AI Gateway・同期境界を、障害注入と同時利用で検証する。

## 10. 再現コマンド

```bash
npm run plan:phase2f:human
npm run eval:phase2f
```

Qwen代表評価は、Ollamaとローカル開発サーバーを起動し、`PHASE2F_QWEN_CASES=10` または `PHASE2F_QWEN_IDS=...` を指定して実行します。評価JSONは固定セットと生成結果を保存し、将来の比較に利用できます。
