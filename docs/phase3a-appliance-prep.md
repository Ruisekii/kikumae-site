# Phase 3A — 避難所アプライアンス準備メモ

作成日: 2026-09-09

## 推奨構成

```text
住民端末 / 職員端末
        │ 避難所LAN
        ▼
  エッジWeb/API + Safety Guard + Local DB
        │ localhost / 同一LAN
        ▼
  Ollama（Conversation 2B / Extraction 4B）
        │ 通信復旧後のみ
        ▼
  Cloud同期ゲートウェイ（将来）
```

公開Cloudflare Workerから家庭PCのlocalhostや避難所LANへ直接接続する構成は採用しない。現行公開版は、公開環境でlocal-rules fallbackを使うという制約を明示する。

## 最低限の起動前チェック

- エッジ端末の時計を日本時間に合わせる。
- Web/API、D1相当のローカルDB、Ollama、モデルのロード状態を確認する。
- Safety-onlyリクエストを1件通し、LLM停止中でも応答することを確認する。
- 住民のテスト相談を1件送り、確認URL、職員画面、公開ステータス更新を確認する。
- Ollama停止時に相談原文が保存され、local-rulesに切り替わることを確認する。
- バックアップの保存場所、暗号化、復元担当、復元時刻を記録する。
- 共有端末のブラウザ履歴、localStorage、確認URLを運用終了時に扱う手順を決める。

## まだ作っていないもの

- D1の本番バックアップ／復元コマンド。
- 完全自動のエッジインストーラー。
- オフライン送信キューと再送のUI。
- モデルを含む端末イメージ。
- LAN内認証、端末証明書、複数避難所同期。

上記は、端末・OS・DB・バックアップ要件が決まる前に作ると誤運用を招くため、Phase 3Aでは設計準備に留める。

## 運用停止条件

- Safety-only経路が通らない。
- 相談原文を保存できない、または保存状態を表示できない。
- LLM停止時にlocal-rulesへfallbackしない。
- 職員の内部メモが住民公開プレビューに混ざる。
- 時計がずれて受付・更新時刻を信頼できない。
- バックアップの復元担当と手順が不明。
