# Phase 2F/2G checkpoint

作成日: 2026-09-09

## 目的

Phase 2F の職員負担評価と Phase 2G の敵対的・境界ケース評価を、同じ固定データで再実行可能な状態にする。公開版、実データ、既存の評価データは変更しない。

## 実施したこと

- Phase 2G 固定ケースを 170 件に拡張した。
  - 既存 Phase 2F の 100 件を再利用。
  - 怒り・侮辱、短文、訂正、Safety 境界、複合相談、多言語、誤字・音声認識ノイズを各 10 件追加。
- `scripts/phase2g-eval.mjs` を追加し、HTTP、事実保持、文脈、要望、感情、不確実性、訂正、Safety、証拠アンカー、レイテンシを記録するようにした。
- Phase 2G の評価時だけ、環境変数で明示的に有効化した eval-suite ヘッダーに限り rate limit を回避するようにした。公開版の通常リクエストには適用されない。
- Safety Guard の明らかな境界漏れを最小限修正した。
  - 「胸が少し痛い」を検知。
  - 「倒れた／起きない」および薬の期限表現を検知。
  - 英語・中国語・韓国語の薬・重大体調表現を補完。
  - 「息苦しくはありません」の否定を維持しつつ、同じ文の煙など別の危険兆候を抑制しない。
- 評価スクリプトの言語別集計再帰バグと、Safety の否定・不確実性の判定バグを修正した。

## 解釈

- Safety Guard はこの固定・合成評価セットでは、今回の境界修正後も false negative 0、false positive 0 だった。ただし、これは実災害の真値を使った検証ではなく、Safety の実運用保証ではない。
- Phase 2E の小規模な成功結果は、170 件に拡張するとそのまま再現しなかった。特に Incident Card の事実保持と多言語の構造化が未成熟である。
- 証拠アンカーは保守的に実装されており、原文にない情報を付け足す hallucination は検出されなかった。一方、保守的すぎることによる取りこぼしが大きい。
- 初回実行では 30 件以降が rate limit になり、評価集計にも再帰バグがあった。いずれも評価ハーネス側の問題で、公開アプリの正常性を表す結果ではない。eval-suite の明示的なローカルゲートと再帰修正後、170/170 HTTP 200 を再確認した。

## 判断

- Safety Guard の今回の最小修正は採用する。
- 「多言語対応済み」「職員向け構造化が十分」とは扱わない。
- 評価期待値を緩めて数値を改善することはしない。
- 一般的なキーワードを大量追加して自動分類を強めることは保留する。次の改善は、誤分類と取りこぼしを含むラベル付きケースを追加し、医療・安全・物資の優先順位を明示した上で行う。
- Phase 2H のオフライン／音声／アクセシビリティ監査と Phase 2I の脅威モデルを先に進める。

## 次の検証

1. Web UI、Qwen、Safety、翻訳、音声、職員画面のオフライン分類。
2. オフライン時に相談原文が失われないか、再送・保留できるかの障害試験。
3. 権限、入力、原文・内部メモ・監査ログのデータ境界を確認。
4. 実施できない実機・ネットワーク試験は未実施として記録し、推測で補わない。
